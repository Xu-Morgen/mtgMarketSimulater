# ADR-003：分阶段以 Leyline 数据训练并人工发布本地 ML 卡组评分模型

日期：2026-07-29

状态：已采纳；替代 ADR-002 的首发后长期评分策略部分

## 背景

I24R 的规则化本地原型只在小型受控样本中得到验证，不能直接成为比赛主评分。产品需要先用 Leyline 取得稳定且可审计的标签，再在数据量和泛化验证足够时，由管理员将经过验证的机器学习模型发布为新报名的主评分源。

## 决定

### 阶段 1：Leyline 数据积累

- 首发评分策略为 `leyline-only/v1`。仅报名命令可调用 Provider；输入只含已验证、规范化的 Commander `decklistText` 与 `format=commander`，不发送玩家身份、库存、余额、报名费、订单或赛事数据。
- 每次通过 schema/内容校验的 Leyline 响应保存为只追加的服务器专用源记录：完整响应密文、响应 SHA-256、Provider/适配器版本、请求卡表 SHA-256、解析/缺失卡、`isStale`、`computedAt` 和关联报名评分快照。完整原文不进入玩家 DTO、浏览器日志或通用管理日志；管理员仅能查看脱敏摘要和训练批次清单。保留与访问须符合 Provider 使用条款。
- 结算只读取报名时的评分快照，绝不因新增 Leyline 数据、再训练或策略发布而重算既有报名、赛事、奖励或排名。

### 阶段 2：离线训练与验证

- 训练任务只能从已批准、去标识化的源记录读取卡表特征和 Leyline `scores.power` 标签；不得读取用户身份、余额、库存、订单、奖励、赛果或管理操作内容。
- 规则标签模型是特征识别与解释层，不是最终强度裁决层。它必须输出全部整数化特征：土地数量与法术力曲线；抓牌、加速、去除、反制、导师与快速法术力数量；无限组合件与致胜组合件；墓地、神器、结界交互能力；核心组件的组内冗余度；明确获胜路线；以及 Commander 的 Game Changer、禁牌和 Bracket 条件。模拟与 ML 模型只消费这一版本化特征向量校准最终 0–100 分；禁牌和赛制/Bracket 条件仍由合法性规则硬拒绝，不能被任何评分抵消。
- 每次训练产出不可变模型工件、特征/训练代码版本、数据集 manifest（仅快照/卡表摘要哈希）、训练随机种子、超参数、训练/验证/留出集指标、偏差报告和模型 SHA-256。管理员可用带原因与 `Idempotency-Key` 的命令开始、重试或停止训练，但不能编辑标签、覆盖工件或把训练中模型用于报名。
- `ml-eligibility/v1` 的首次发布门槛为：至少 1,000 份不同的规范化卡表摘要；Leyline Bracket 1–4 各至少 100 份；按卡表摘要分组的 70/15/15 训练/验证/独立留出集；独立留出集覆盖率至少 98%、平均绝对误差不高于 5 分、P95 绝对误差不高于 10 分、单调性至少 9,500 bp，且 Provider 分数 ≤25 与 ≥75 两端的平均绝对误差均不高于 6 分。任一门槛不通过即只能保留候选工件。

### 阶段 3：人工发布评分策略

- 管理员只能经“草稿 → 服务端预览 → 二次确认发布”的版本化策略命令选择优先级。首发为 `leyline-only/v1`；通过 `ml-eligibility/v1` 且人工审阅的模型可发布为 `ml-primary-leyline-fallback/v1`。策略、模型版本和批准报告必须写入审计，并随每份新报名快照保存。
- 发布只影响发布后创建的新报名。模型推理失败时按已发布策略回退 Leyline；两个来源都不可用时，必须在收费、库存锁定和创建报名之前失败。管理员不得通过浏览器直接填写分数或修改任一历史快照。
- 规则化 `local-deck-power/*` 原型仍只服务于研究；它不是此 ADR 所称的 ML 模型，也不会被此策略自动启用。

## 后果

I24B 需首先实现 Leyline 完整评价的受控、只追加留存与 `leyline-only/v1` 快照；训练、模型工件、人工发布和管理页面作为独立的 I33B/I33F 轨道实施。`DeckPowerSnapshotDto` 扩展 `ml` 来源只是未来持久化契约，不代表模型已训练或可被选中。
