## FE-M05：待履约确认与取消（AT-06 浏览器路径）

- 前置数据：I20B 已完成模拟履约后端；两个玩家经服务端撮合产生成交（数量 2、成交价 200、order_fee 单位 4、保证金单位 20、履约期限派生自 `bilateral_order_limits.ttl_seconds`），成交状态为 `matched_pending_fulfillment`。
- 操作步骤：买方/卖方分别打开 `/orders`，在「我的成交与待履约资产」核对成交明细（角色、SKU、数量、成交价、order_fee、待履约资金、待履约库存、状态、履约期限、规则版本、成交时间）、无实体物流声明与操作列「确认履约」「取消履约」。点击「确认履约」打开二次确认弹窗，核对成交 ID、待履约资金拆分（买方=数量×成交价+order_fee、卖方=保证金）、待履约库存、履约期限、确认/取消后果说明与无物流声明；二次确认后核对成功横幅（状态推进为「已完成」、关联成交 ID）与失败场景。再以卖方视角执行「取消履约」，核对退回资金/扣除保证金/恢复库存的差异说明。
- 预期结果：履约/取消只提交一次（幂等键 + tradeId 指纹），提交期间按钮禁用、双击不重复请求；成功后成交状态、余额、库存、保证金、账本与审计按服务端响应刷新，前端不结算或推导。到期由服务端（order.expire）推进为已取消的成交不可操作（无按钮、显示「不可操作」）。履约失败返回 `RESOURCE_CONFLICT` 时显示服务端原因并提示刷新成交列表，不伪造成功。页面在两处明确声明「不涉及实体卡牌物流、发货或退货」。
- 实际结果：通过。买方页面展示待履约成交「买方 · 408 游戏币」、履约期限列与无物流声明；确认履约弹窗展示成交明细、待履约资金「408 游戏币（数量×成交价 + order_fee）」与履约期限；双击确认只发 1 个 POST（幂等键符合 UUID 格式），成功后显示「履约已完成」并附带关联成交 ID `trade-i20f-1`。卖方取消履约展示「你的保证金将被扣除、待履约库存将恢复」，成功后显示「履约已取消 · 你的待履约资金已退回」。到期已取消成交显示「已取消」「不可操作」且无操作按钮。`RESOURCE_CONFLICT` 失败显示行内错误与「刷新成交列表」按钮，无伪造成功。窄屏 390 × 844 二次确认弹窗与无物流声明自适应可见。
