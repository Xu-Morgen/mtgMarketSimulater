## FE-M05：库存估值、NPC 卖出与失败恢复

- 操作步骤：进入“我的库存”，核对 API 返回的单张现价、全部持仓市值、未实现盈亏、可用量和订单/比赛锁定量；打开可用 SKU 的“向 NPC 卖出”，依次输入指定数量、选择“全部可用库存”，核对服务端预览中的数量、收入、费用、报价有效期与额度后确认。分别模拟全部锁定、预览时库存不足、收购价变化；在确认时快速双击并在成交后刷新页面。
- 预期结果：页面不以可用量或成本自行计算估值/盈亏；锁定卡不进入卖出；`all` 由服务端解析；确认只发送报价标识、版本、解析后的数量和最低单价。库存不足与报价变化不产生本地余额/库存结果，重新预览后才可恢复成交；快速双击只发送一个 HTTP 成交请求，刷新后重新读取服务端持仓。
- 实际结果：通过。展示服务端单价 150 游戏币/张、市值 750 游戏币、未实现盈亏 150 游戏币；`all` 解析为 3 张并显示收入 510 游戏币、费用 60 游戏币。全部锁定时入口为“无可用库存”；库存不足和报价变化均禁用确认或要求重新预览。确认同步锁使快速双击只产生一笔 POST，刷新后展示 API 返回的 0 可用量。
- 证据：`apps/web/tests/e2e/npc-sell.spec.ts` 覆盖成功/刷新、锁定/数量不足和报价变化/指定数量；桌面与窄屏均执行。请求断言验证 POST 不含浏览器计算的总额、费用、库存或盈亏。
