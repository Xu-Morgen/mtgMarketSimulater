## FE-M07：管理员导航、深层链接与权限

- 前置数据：管理员会话恢复 cookie；管理 API mock 返回首页/活动/玩家/日志/任务数据。
- 操作步骤：
  1. 管理员登录后进入 `/admin`，核对环境标识、目录/价格新鲜度、失败任务、活动数量、待复核异常与最近操作摘要。
  2. 依次进入「内容、活动、玩家、任务、日志」，每个页面均保留加载/空态/错误边界。
  3. 以普通玩家直接访问 `/admin/events`、`/admin/users`、`/admin/logs`，并请求对应管理 API。
- 预期结果：管理员侧栏可见全部管理入口；玩家侧栏无管理入口；玩家深层链接显示 403 页，管理 API 返回 403。
- 实际结果：通过。首页正确显示环境、新鲜度（新鲜/过期/不可用）、失败任务数、活动数和最近审计摘要；玩家无任何管理入口，深层链接显示「无权访问此页面」，`/v1/admin/dashboard` 对玩家返回 403。
- 证据：`admin-i30f.spec.ts`「管理员首页…」「普通玩家没有…入口，深层链接 403，管理 API 返回 403」两项通过。
- 结果：通过。

## FE-M08：活动完整生命周期

- 前置数据：活动草稿夹具 `summer-2026`（全服、因子 12000 bps、区间 2026-07-31 → 2026-08-31）；预览返回 previewVersion 2、无冲突、预计重价任务。
- 操作步骤：
  1. 在 `/admin/events` 填写代码、名称、展示文案、本地开始/结束时间（页面标准化为 UTC 提交），点击「保存草稿」并二次确认。
  2. 在列表中点击「预览」，查看服务端预览的作用域、因子范围、预计重价任务与冲突。
  3. 点击「确认」发布，等待成功提示与列表状态更新。
- 预期结果：保存只创建草稿；预览在发布前展示范围、版本、冲突与预计任务；发布使用预览版本 + 幂等意图，成功后状态变为已发布；草稿与发布各只投递一次。
- 实际结果：通过。草稿保存仅触发 1 次 POST `/v1/admin/campaigns`；预览展示「预计重价任务」且无冲突；发布仅触发 1 次 `/publish`；「活动已发布」提示出现。
- 证据：`admin-i30f.spec.ts`「管理员创建活动草稿、预览后发布；提交中按钮禁用且不重复投递」通过；断言 `draftCalls === 1`、`publishCalls === 1`。
- 结果：通过。

## FE-M09：玩家管理与补偿修正

- 前置数据：玩家 `loop@example.test`（余额 9000、1 个活跃会话）；冻结原因「可疑操作」；余额补偿 +1000。
- 操作步骤：
  1. 在 `/admin/users` 按用户名检索玩家，打开详情，核对账户余额、会话数与状态。
  2. 点击「冻结」，填写原因并二次确认；核对成功提示与状态更新。
  3. 点击「余额补偿」，选择原因分类、填写说明与金额，先「预览并确认」再「二次确认提交」，核对补偿结果（审计 ID、新流水 ID、新余额）。
- 预期结果：检索/详情只读；冻结/解冻/会话撤销显示影响范围和服务端状态；补偿只提交命令，不接受「最终余额」自由编辑，并展示新生成流水与审计；每项操作都使用独立幂等意图。
- 实际结果：通过。冻结仅触发 1 次 `/freeze`；补偿仅触发 1 次 `/compensate/balance`；补偿结果展示 `ledger-1` 流水 ID 与新余额；详情页不存在「最终余额/最终库存」输入框。
- 证据：`admin-i30f.spec.ts`「管理员检索玩家、冻结并执行余额补偿；补偿只提交命令并展示新流水」通过；断言 `freezeCalls === 1`、`balanceCalls === 1`。
- 结果：通过。
