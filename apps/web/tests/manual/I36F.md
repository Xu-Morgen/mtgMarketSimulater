# I36F：新手引导完整流程审计与人工验收

日期：2026-08-06（`onboarding/v3`、九步玩家循环与 Tour 状态机修复）

## 审计结论与修复清单

### 流程完整性

- [x] 原流程购买/开包/交易后直接进入报名，却没有独立组卡步骤；现新增 `create-first-deck`，只在服务端保存的合法 Commander 卡组存在时完成。
- [x] 原报名步骤同时写着“构筑合法卡组并报名”，但服务端只检查报名表，教程文案和完成事实不一致；现拆为组卡与报名两个步骤。
- [x] 原教程以报名为终点，没有教玩家等待结算、查看排名、胜负、奖励和重放；现新增 `finish-first-tournament`，页面取得服务端已结算结果并实际展示后才提交 view_event，服务端再次核对该玩家确有结算结果。
- [x] 原“收藏见涨”由“持有任意库存”自动完成，玩家不访问图鉴也算学会；现改为 `/collection/album` view_event。
- [x] 完成最后一步后原 Tour 直接消失，玩家不知道还有完成奖励；现自动返回 `/onboarding` 展示领取入口。
- [x] 若卡组库存没有传奇生物，编辑器明确说明 Commander 前置并提供返回市场购入的路径；不再把玩家送到必然失败的报名弹窗。
- [x] 原“去市场购买传奇生物”只是普通 `/market` 链接，Tour 到市场后找不到组卡锚点，只能再次提示跳卡组页并用遮罩阻断购买；现市场进入指挥官采购模式，首屏直接显示推荐传奇生物与买入按钮并隐藏行情/指数/公告，成交后刷新卡组库存并自动返回原构筑。普通市场交易列固定在右侧，1080p 与窄屏无需横向滚动寻找买入入口。
- [ ] 产品后续评估：是否增加“卖出单卡/挂单与履约”进阶教程。它们不阻塞当前首次核心循环，暂不混入 9 步基础教程。
- [ ] 产品后续评估：是否提供确定性的“新手指挥官”获得方式。当前教程能解释并恢复，但开包/NPC 首购不保证一定获得传奇生物，可能增加首次完成时长。

### 自动推进与时机

- [x] 原推进依赖捕获鼠标是否点过当前 DOM 锚点，键盘、后台 profile、view_event、跳过或等价入口完成时会漏跳；现只认同一服务端步骤 `completion: null → auto|skip`。
- [x] 原开包被硬编码为永不自动推进；现完成后等待翻牌动画状态 `complete`，再延迟 650ms 进入价格页，避免过早切走。
- [x] 原价格浏览、收藏浏览和 profile 完成被硬编码为不推进；现服务端确认后统一自动前进。
- [x] 原跳过后代码不前进，但人工文档写“自动前进”；现代码和验收统一为服务端确认跳过后自动前进。
- [x] 原未完成步骤只要锚点存在，Tour 主按钮就显示“下一步”，允许绕过服务端目标；现显示并禁用“请完成高亮操作”。
- [x] 原同页锚点晚挂载会居中卡死；保留 200ms 锚点生命周期检测并强制重新定位。
- [x] 原路由门禁只等目标 pathname，到达失败时可永久禁用；现 8 秒后恢复并允许重试。
- [x] 组卡保存成功原只刷新 decks，不刷新 onboarding；现同步失效 onboarding，服务端合法卡组 profile 会及时推进。
- [x] 赛事结果首次返回 404“尚未结算”后原查询停止轮询；现仅对 `RESOURCE_NOT_FOUND` 每 3 秒继续，其他错误停止并显示重试。
- [x] 赛果到达后原不刷新 onboarding；现结果组件使 onboarding 失效，完成第 9 步。
- [x] 原价格历史页挂载后立即提交 view_event，约数百毫秒便跳往市场，玩家没有阅读机会；现页面就绪后至少保留 6 秒，并要求玩家点击“我已查看价格走势”才提交。
- [x] 原首笔交易只框选普通市场第一张“向 NPC 买入”，同步后 SKU 全部停用或列表为空时高亮目标不存在；现服务端在该步骤优先选取一张可用持仓做保底卖出，无合适持仓才选可负担买入，返回不可变报价预览。
- [x] 保底例外只允许当前步骤、服务端指定的 SKU/报价和 1 张；不支持“全部卖出”或数量放大，成交仍使用标准账本、库存、事实、审计与幂等事务，步骤完成后例外立即撤销。

### 目标锚点与异常恢复

- [x] 创建存档后首页分支切换、工作资金卡片晚挂载。
- [x] 工作资金步骤优先框选领取按钮并在按钮上方展示气泡；不再用整张卡片居中定位而遮挡按钮，说明文案不出现 `undefined`。
- [x] 后续步骤不再把价格图、收藏页、卡组库存和赛事整页作为首选目标，改为标题/状态等小锚点；交互控件采用顶部气泡，非交互状态采用底部气泡。
- [x] NPC 普通买入和保底卖出都按“入口 → 获取服务端预览 → 确认成交”切换目标；赛事报名按“选择卡组 → 确认报名”切换目标，避免气泡指向禁用按钮并遮挡真正的前置操作。
- [x] 多张可交易卡/多场比赛不再生成重复引导 id：市场只标记当前页第一张可交易卡，赛事只标记第一场可报名赛事及第一场已报名赛事，避免 Tour 定位到错误或禁用按钮。
- [x] Tour 固定 520px 宽度已增加视口上限，操作区允许换行；390px 窄屏不再因气泡宽度产生横向遮挡。
- [x] 气泡宽度只设置在每一步 Trigger popup；禁止通过 Tour 根 `className/style` 设置宽度，因为 rc-tour 会把根样式复用到全屏 mask，造成遮罩在 520px 处分裂、右半屏漏光。
- [x] 开包/NPC 买入/NPC 保底卖出/报名弹窗打开后，目标从页面入口切换到当前可操作的预览或确认控件。
- [x] 组卡从列表入口切换到编辑器；编辑器按“缺少指挥官/选择指挥官/100 张检查/合法后保存”动态定位。
- [x] 页面无目标、数据空态或可用比赛为空时保持居中说明与“去完成”入口，不伪造完成。
- [x] 玩家显式关闭后不会在引导页自动重启，必须从入口再次开始。
- [x] 旧版已领取奖励玩家迁移后保持完成，不因 v3 新步骤重新出现待办。

## 九步完整验收

1. 从未建档玩家首页启动 Tour，创建存档后自动定位同页工作资金的领取按钮；确认气泡位于按钮上方、不遮挡按钮且文案无 `undefined`，领取后自动跳 `/packs`。
2. 打开购买弹窗，目标切到确认按钮；服务端开包完成时仍停留展示翻牌，动画全部结束后才自动跳 `/market/history`。
3. 价格页加载后先阅读曲线：前 6 秒按钮禁用，期间 URL 保持 `/market/history` 且不得提交 view_event；点击“我已查看价格走势”后只提交一次，服务端确认后自动跳 `/market`。失败时留在当前步并允许重试。
4. 把普通报价设为空或全部停用：市场仍显示“新手保底交易机会”，优先用开包持仓卖出 1 张；弹窗固定数量 1、没有“全部可用库存”，目标从入口切到卖出确认按钮。成交后自动跳 `/collection/album`；刷新或伪造数量 2/`all` 均不能继续使用例外。
5. 图鉴页只提交一次收藏 view_event；服务端确认后自动进入 `/decks`，进度应为 6/9。
6. 无卡组时进入 `/decks/new`：若没有传奇生物，点击采购链接进入带 `cardRole=commander` 的市场，确认列表只包含传奇生物，Tour 高亮买入/预览/确认且不再提示跳回卡组；成交后自动返回 `/decks/new` 并高亮新卡的“设为指挥官”。随后填写名称，用同色虚拟基本地补足 100 张；不足 100 张时定位编辑区，100 张时定位服务端检查，检查合法后定位保存。
7. 保存非法草稿不能完成组卡步骤；保存合法草稿后自动跳 `/tournaments`，当前步变为首次报名。
8. 报名弹窗选择合法卡组并确认；报名成功后当前步变为“查看比赛结果”，页面显示自动刷新提示，不重复收费或重复报名。
9. 结算前 404 不停止轮询；赛果出现后展示排名、胜平负、奖励和重放材料，Tour 自动关闭并返回 `/onboarding`。
10. 领取 500 游戏币完成奖励：二次确认、双击只投递一次、成功金额与余额取服务端响应；首页 `continue_onboarding` 待办消失。

## 交互与恢复验收

1. 任一未完成且有锚点的步骤，主按钮必须禁用为“请完成高亮操作”，不能跳过事实；“跳过此步”仍是独立幂等命令。
2. 跳过后自动进入下一个服务端未完成步骤；上一步可查看已跳过状态，但不能重复跳过。
3. 关闭 Tour、刷新、跨页返回后进度不回退、不由浏览器补写；“开始引导/继续引导”从服务端 `currentStepId` 恢复。
4. 模拟目标锚点晚 1–2 秒挂载、路由失败、请求错误、空报价、无赛事和无传奇生物，确认均有可理解且可重试的状态。
5. 在桌面和 390 × 844 重复完整路径，确认遮罩始终覆盖整个视口且只在当前目标处留出高亮孔洞；Tour 气泡宽度保持在视口内、底部操作可换行，业务弹窗、卡组表格滚动和按钮均可操作，气泡矩形不与当前高亮目标相交。
