构建：本工作区 I31F 变更集；独立临时 SQLite 与 Next 构建目录，不使用开发数据库。

## 环境

- 浏览器：Chromium 桌面与 390 × 844 窄屏。
- 测试账号：`i31f-player@example.test`（受控夹具玩家，仅用于路由 mock；未记录密码、令牌或 Cookie）；`i31f-admin@example.test`（受控夹具管理员，用于备份状态与下载/演练）。
- 服务端事实：备份/导出文件、状态、SHA-256、完整性、过期时间和保留策略均由 `apps/api` 的 `/v1/admin/backups*` 与 `/v1/exports*` 返回；本页只读展示并提交生成/下载/演练意图，不在浏览器结算、推导或拼装 CSV/报表内容。
- 自动化佐证：`apps/web/tests/e2e/exports-i31f.spec.ts`，chromium 与 narrow-chromium 两项目各 4 passed；`pnpm check` 通过。

## FE-M10：玩家数据导出与下载

- 前置数据：玩家导出夹具 `export-i31f-1.csv`（succeeded、256 字节、过期时间 2099）；下载接口返回服务端已转义的 CSV 样例（`'=evil|cmd` 前置单引号）。
- 操作步骤：
  1. 玩家登录后进入 `/exports`，核对导出说明（服务端生成、CSV 公式注入防护、过期自动清理）。
  2. 选择 CSV 格式，点击「生成导出」并二次确认；核对成功提示与列表新增的可下载记录。
  3. 在列表中点击「下载」并二次确认；核对浏览器下载文件名与内容。
- 预期结果：生成以独立幂等意图投递（同一网络重试不重复生成）；下载只下发服务端生成的受控 `attachment` 流，文件名来自服务端记录；页面不在浏览器拼装 CSV（无编辑器/文本域承载报表内容）。
- 实际结果：通过。生成仅触发 1 次 `POST /v1/exports`；下载文件名为 `export-i31f-1.csv`；下载文本含 `'=evil|cmd` 前置单引号、不含裸 `=evil|cmd` 公式；页面无 `textbox`。
- 证据：`exports-i31f.spec.ts`「玩家生成导出并下载…下载内容保留服务端公式注入转义」通过；断言 `generateCalls === 1`、`suggestedFilename === "export-i31f-1.csv"`、下载文本匹配。
- 结果：通过。

## FE-M11：过期/失败状态与失败重试

- 前置数据：列表含三条夹具——`export-i31f-1.csv`（可下载）、`export-i31f-2.json`（expired）、`export-i31f-3.csv`（failed，原因「磁盘写入失败」）。
- 操作步骤：
  1. 进入 `/exports`，核对过期记录显示「不可下载」占位且无下载按钮。
  2. 核对失败记录显示失败原因与「不可下载」占位。
  3. 点击「生成导出」重新生成；核对成功提示与列表刷新为新可下载记录。
- 预期结果：过期/失败记录的下载入口被禁用占位替代（非可点按钮）；失败原因可见；重新生成使用新幂等键并成功刷新列表。
- 实际结果：通过。过期行与失败行均无「下载」按钮、显示「不可下载」占位；失败原因「磁盘写入失败」可见；重新生成后列表出现 `export-i31f-retry.csv`。
- 证据：`exports-i31f.spec.ts`「过期与失败记录不可下载并显示原因；失败后重新生成成功并刷新列表」通过。
- 结果：通过。

## FE-M12：管理员备份状态、受控下载与只读恢复演练

- 前置数据：备份夹具 `backup-i31f.db`（scheduled、succeeded、2048 字节、完整性通过、SHA-256 `abcdef12…`）；恢复演练返回完整性通过、核心表存在、采样计数。
- 操作步骤：
  1. 管理员进入 `/admin/backups`，核对摘要统计（总数、成功数、最新成功时间、最新成功 SHA-256 前 12 位）。
  2. 核对页面不暴露源库绝对路径（无 `/home/`）。
  3. 点击「下载」并二次确认；核对浏览器下载文件名为服务端记录的 `backup-i31f.db`。
  4. 点击「恢复演练」并二次确认；核对只读校验结果（完整性、核心表、采样计数）与「未覆盖运行库」声明。
- 预期结果：备份状态/完整性/SHA-256 摘要只读展示；下载只下发服务端受控流、文件名来自服务端记录；恢复演练为只读副本校验、绝不覆盖运行库。
- 实际结果：通过。摘要显示成功备份数与 `abcdef123456`；页面无 `/home/`；下载文件名为 `backup-i31f.db`；演练对话框显示完整性通过、核心表存在、采样计数「用户 5」与「未覆盖运行库」。
- 证据：`exports-i31f.spec.ts`「管理员查看备份状态摘要、受控下载并在只读副本上演练恢复」通过。
- 结果：通过。

## FE-M12-AUTH：备份页面权限隔离

- 前置数据：普通玩家会话（注册新账号）；管理侧栏无「备份」入口，玩家侧栏有「我的数据导出」入口。
- 操作步骤：以普通玩家访问 `/admin/backups` 深层链接，并请求 `/v1/admin/backups` 管理 API。
- 预期结果：玩家无「备份」导航入口；深层链接显示 403 页；备份管理 API 返回 403。
- 实际结果：通过。玩家侧栏无「备份」入口、可见「我的数据导出」；`/admin/backups` 显示「无权访问此页面」；`/v1/admin/backups` 返回 403。
- 证据：`exports-i31f.spec.ts`「普通玩家没有备份入口，深层链接 403，备份管理 API 返回 403」通过。
- 结果：通过。

## 风险与复测

- 无阻断失败。所有页面均通过 Playwright 在桌面与窄屏的自动化佐证；备份/导出文件、状态、SHA-256、完整性、过期、保留策略、用户隔离与 CSV 公式注入防护的服务端权威仍由 `apps/api` 的 I31B 集成测试（`backup-export-routes.test.ts`）保证，本页只读展示并提交意图，不绕过任何服务端校验或直接改表。
