## 特殊点与风险

- 权威边界：所有页面只展示服务端结果并提交写意图；浏览器不结算、不推导余额/库存/报价/赛果/奖励/掉率，不复制可结算规则。补偿修正只提交补偿命令，不允许输入“最终余额/最终库存”。日志页只读，不提供删除或修改；详情仅展示写入方已脱敏的摘要，不渲染密码哈希/令牌/Cookie/密钥/Provider 原文。
- 幂等与审计：所有写 mutation 在组件层生成 `Idempotency-Key`，同一网络重试复用键、重新预览或参数变化才换键；成功只失效相关服务器真相缓存。金额、库存、流水、赛果、奖励、保证金与审计的服务端权威仍由 I30B 的 `apps/api` 集成测试与对账保证，前端不绕过任何服务端结算或直接改表。
- 活动生命周期：发布绑定服务端 `previewVersion` 与幂等键；预览展示作用域、因子范围、预计重价任务与冲突，版本过期须重新预览。立即/定时发布使用独立幂等意图；已发布版本不可原地覆盖。
- 安全脱敏：用户详情、日志详情与异常交易均不返回密码哈希、令牌摘要、Cookie、密钥或 Provider 原始响应；Playwright 断言页面无“删除”按钮、无“最终余额/库存”输入框、普通玩家无任何管理入口且深层链接显示 403、管理 API 返回 403。
- 数据兼容性：纯前端实现，无迁移、无契约变更、无运行时数据库改动；`AdminDashboardDto` 等 DTO 全部复用 I30B 已发布的 `@mtg-market/contracts`。
- 已知限制/待决：MTGJSON 草稿「发布」阶段与比赛/成就/奖励配置编辑入口尚未实现（与 I30B 待决项一致），内容页明确不展示这些尚未开放的配置入口；I33 发布后若启用 AI 才追加 Agent 记录页面。
- 验证：`pnpm check`（lint + 全 workspace tsc）通过；`apps/web/tests/e2e/admin-i30f.spec.ts` 在 chromium 与 narrow-chromium 两项目各 5 项通过。
