## 特殊点与风险

- 权威边界：引导步骤完成、跳过、奖励状态全部只展示服务端 `OnboardingDto`；Tour 只标记页面按钮与提交意图（跳过为幂等命令、浏览为 view_event 意图、领取为显式命令），不判定完成、不结算任何经济真相。
- Tour 跨页设计：引导会话状态存于 `OnboardingGuideProvider`（`(player)` 布局持久），切换页面不丢失当前步骤；`useOnboardingQuery` 的 `enabled` 仅在引导会话激活或引导页上为 true，避免每个玩家页面轮询；步骤完成后由五个业务 mutation 追加失效 onboarding 查询驱动 Tour 自动前进。
- 目标按钮高亮：锚点 `#onboarding-*` 存在于对应功能页，Tour 以 `target: () => document.getElementById(...)` 高亮，rc-tour 蒙层对存在目标的步骤不拦截点击（`disabledInteraction` 默认 false）；目标不存在时以居中卡片展示（rc-tour `null` target 语义）。
- 「创建存档」第一步：规则 `onboarding/v2` 新增 `archive_created` profile 步骤（服务端按 `accounts` 快照判定），无存档新玩家当前步骤即创建存档；`onboarding_progress` 以 `step_id` 关联，既有 v1 进度行不受定义变更影响；`rule_versions` 保留 `onboarding/v1` 行供历史进度/发放追溯。
- 幂等与防重复：Tour 跳过采用组件层同步双击锁 + mutation 幂等键（同一意图重试只投递一次）；完成奖励领取沿用既有二次确认 + 幂等键。
- 回归范围：常驻 Tour 仅在引导会话激活或引导页上请求 `/v1/onboarding`，既有页面 e2e 不受影响；onboarding fixture `ruleVersion` 统一 v2（`steps` 为空数组的旧 fixture 兼容，`totalCount` 不作为展示断言依据）。
- 待决：无。e2e（`apps/web/tests/e2e/onboarding-i36f.spec.ts` 桌面 + 窄屏）与人工验收由用户按 AGENTS.md 第 7 节在本机手动执行并补登。
- 验证：`pnpm check`（lint + 全 workspace tsc）通过；contracts 17、rules 101、database 4、api 257（1 跳过）、web 5 全过；`next build` 通过（`/onboarding` 路由生成）。
