## 特殊点

- 权威边界：浏览器只提交 `{quoteId,quoteVersion,previewVersion,quantity,limitPrice}`；`previewVersion` 为 64 位 hex 原样回传，`limitPrice` 为整数最小货币单位，限价带、费用、保证金、预计金额、可用量全部只展示服务端 DTO，绝不回传或本地重算。真正的限价边界由服务端 `order/v1` 以 `RULE_VIOLATION` 兜底，浏览器即时校验仅作反馈。
- 幂等与双击锁：同一 `(skuId,quoteId,quoteVersion,previewVersion,quantity,limitPrice)` 网络重试复用幂等键；任一变化（含重新预览得到新 `previewVersion`）才换键。同步 `confirmationLock` ref 在 `mutate` 前置位，防止 React `disabled` 渲染生效前的同一事件循环第二击发出第二个 HTTP 创建请求（照搬 I16F `npc-sell-dialog`）。
- 缓存失效：创建/撤单成功仅失效 `orders / archive / ledger / inventory / market* / prices.public-status`，不写 Zustand 或本地副本。
- `VERSION_STALE`：报价/预览过期必须重新预览，不能用旧 `previewVersion` 重试；重新预览自动 `beginNewIntent` 丢弃旧幂等键。
- 兼容性：无数据库迁移、无 contracts/端点变更、无后端代码改动；I18F 只消费已完成的 I18B 后端。
- 延后项：撮合、模拟履约、`p2p.trade.settled` 与 `order.expire` 延后至 I19B/I20B/I22B；本迭代订单只处于 `open` 状态，页面不展示撮合/履约 UI。
- 验证：已通过 `pnpm --filter @mtg-market/web check`（eslint + tsc --noEmit）、`pnpm --filter @mtg-market/web exec playwright test tests/e2e/orders.spec.ts --workers=2`（桌面与窄屏共 14 项全绿）与全 workspace `pnpm check`。
