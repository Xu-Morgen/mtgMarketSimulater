# I19F 实施计划：双边订单簿与撮合状态页面

## 背景与权威边界

I19F 要求向玩家展示服务端撮合顺序、成交和待履约状态。I19B 已完成后端撮合（`bilateral_trades` 表、`OrderService.match`、`GET /v1/orders/book/{skuId}`、admin `POST /v1/orders/{skuId}/match`），但**玩家无法看到自己的成交与待履约资产**——撮合结果 `MatchResultDto` 只返回给 admin。权威边界（AGENTS.md §2）要求浏览器不得推导成交/资产状态，因此必须新增一个**只读、服务端真相**的玩家成交查询接口。

## 1. 共享契约 `packages/contracts/src/index.ts`

新增玩家视角成交 DTO（脱敏对手身份、附玩家角色与待履约资产），与现有 `BilateralTradeDto` 并列：

```ts
/** I19F 玩家视角的单笔 P2P 成交；对手身份脱敏，附当前玩家角色与待履约资产。 */
export interface PlayerBilateralTradeDto {
  id: string;
  skuId: string;
  /** 当前玩家在本笔成交中的角色。 */
  role: "buyer" | "seller";
  /** 当前玩家自己的委托 ID；对手委托 ID 不暴露。 */
  myOrderId: string;
  quantity: number;
  /** 取 maker（先入订单簿一方）限价的成交价。 */
  executionPrice: Money;
  /** 当前玩家本笔已成交 order_fee（买方/卖方各自的单位费用×数量）。 */
  fee: Money;
  /** 当前玩家本笔待履约资产：买方=待履约资金（数量×成交价+order_fee），卖方=已成交保证金。 */
  pendingFunds: Money | null;
  /** 仅卖方填充：本笔已离开持有的待履约库存数量。 */
  pendingInventoryQuantity: number | null;
  /** 撮合规则版本，可追溯价格—时间优先与成交价取 maker 的语义。 */
  ruleVersion: string;
  status: BilateralTradeStatus;
  createdAt: string;
  updatedAt: string;
}
```

为契约补充对应单测断言（`src/index.test.ts`，仅类型存在性，与现有风格一致）。`pnpm --filter @mtg-market/contracts test`。

## 2. 后端只读接口 `apps/api`

### 2.1 `OrderService` 新增 `listPlayerTrades`

在 `application/order-service.ts` 新增 `listPlayerTrades(userId, filters: { skuId?; cursor?; limit })`：
- 查询 `bilateral_trades WHERE buyer_user_id = ? OR seller_user_id = ?`，按 `created_at DESC, id DESC` 分页（复用 `bilateral_orders` 列表的 cursor 语义：整型 offset）。
- 每行映射为 `PlayerBilateralTradeDto`：`role` 由 `buyer_user_id === userId` 决定；`myOrderId` 取对应方 order id；`fee` 取 `buyer_fee_amount`/`seller_fee_amount`；`pendingFunds` 买方=`quantity*execution_price + buyer_fee`、卖方=`seller_fee_amount`（已成交保证金）；`pendingInventoryQuantity` 卖方=`seller_inventory_quantity`、买方=`null`。**不返回对手 userId、对手 orderId、hold id。**
- 纯读、不写事务、不调幂等键。

### 2.2 新路由 `GET /v1/orders/trades`

`api/order-routes.ts` 增加（`preHandler: requireRole("player")`），query 经 zod 校验 `skuId?(uuid)`、`cursor?(/^\d+$/)`、`limit(1..100, default 20)`，返回 `success(request.requestId, { items, page })`。无写、无幂等键、无审计（只读）。

### 2.3 OpenAPI 与文档

- `src/openapi.ts`：`publicApiPaths` 与 `paths` 登记 `GET /v1/orders/trades`。
- `apps/api/docs/api/README.md`、`apps/api/docs/operations/README.md`、`apps/api/ARCHITECTURE.md`：新增 I19F 玩家成交只读接口说明（脱敏对手、附待履约资产、不改经济状态）。
- `后端需求.md`：在 I18/I19B 段补 `GET /v1/orders/trades` 条目。

### 2.4 后端集成测试 `order-routes.test.ts`

新增 `I19F 玩家成交只读视图` 测试组（复用现有 `createTestApp`/`player`/`seedSellerAndSell`/`createBody` 夹具），覆盖：
1. 全量撮合后，买方经 `GET /v1/orders/trades` 看到自己是 buyer、成交价取 maker、待履约资金、不含对手 userId/orderId/holdId；卖方看到自己是 seller、待履约库存数量与保证金。
2. 部分撮合：买卖双方各自看到自己的成交行，`role` 正确，待履约资产切分正确。
3. 分页与只返回自己的成交（无关玩家看不到他人成交）。
4. `skuId` 过滤生效；对手身份字段不出现在响应中（断言无 `buyerUserId`/`sellerUserId`/`buyOrderId`（对手方的）/`*HoldId` 字段）。
5. 自成交场景无成交记录，列表为空。

## 3. 前端 `apps/web`

### 3.1 API 层 `api/orders-api.ts`

- 新增 `bilateralOrderApi.trades(accessToken, filters)` → `GET /v1/orders/trades`。
- 新增 `usePlayerTradesQuery(filters)`：queryKey `["orders","trades",user.id,filters]`，`enabled` 同现有 hooks，`retry: false`。
- **轮询与过期提示（I19F 要求）**：给 `useOrderBookQuery` 和 `usePlayerTradesQuery` 增加 `refetchInterval`（默认 10s，与 admin 同级量级；查询失败时不轮询）与 `refetchIntervalInBackground: false`。连接失败时组件显示「数据可能过期，正在重试」提示（用 `isError`/`isStale`）。
- `useCreateOrderMutation` 与 `useCancelOrderMutation` 的 onSuccess 失效列表追加 `["orders","trades",user.id]`（订单簿已在 create 列表中；cancel 列表也补 trades）。

### 3.2 增强 `/orders` 页面 `features/orders/orders-page.tsx`

页面顶部新增四个区块（服务端真相投影，沿用 dashboard `<article><span>/<strong>` + `formatMoney` 与 Ant `<Table>`/`<Tag>` 模式）：

1. **余额状态卡**：复用 `useArchiveQuery`，展示总额/可用/冻结（与 dashboard 一致文案）。撮合后冻结额随待履约资金变化，由服务端返回。
2. **双边订单簿面板**：SKU 选择器（下拉，默认当前玩家最近一笔未完成委托的 `skuId`；可手动切换并写入 URL `?skuId=`）；展示买单（按服务端价格降序）与卖单（升序）各 N 档：限价、剩余数量、委托数；附 `capturedAt` 时间与轮询刷新；`bids/asks` 全空时显示空态；查询失败显示「订单簿数据可能过期，正在重试」。
3. **成交记录表格**：`usePlayerTradesQuery`，列：角色（买/卖 Tag）、SKU、数量、成交价、我的费用、待履约资金、待履约库存、规则版本、状态（`matched_pending_fulfillment`→「待履约」）、创建时间；空态、加载骨架、错误重试；轮询刷新。

## 关键边界与风险

- **权威边界**：新增 `GET /v1/orders/trades` 是纯只读查询，不改经济真相、不写审计、不引幂等键；玩家视角 DTO 脱敏对手 userId/orderId/holdId，符合 §6 安全约定。
- **轮询安全**：`refetchIntervalInBackground:false`，玩家切后台不轮询；失败不轮询避免风暴；只接受服务端状态，连接失败显式提示「可能过期」。
- **不越权**：玩家无法经新接口看到他人成交或订单簿中的用户身份（订单簿本就不含身份）。
- **延后项**：履约确认/取消（I20B/I20F）、`order.expire`（I22B）不在本期；待履约资产本期只展示，不可操作。
- **不修改**：规则包（`packages/rules` 撮合规则 I19B 已完成，I19F 不改规则）、数据库迁移（`bilateral_trades` 已存在，无需新迁移）。
