# MTGJSON 报价刷新 + 流式下载解析 + job 恢复与重跑

## 背景
报价全部 stale（`valid_until` 钉在两天前），根因：①报价刷新依赖 `prices.sync` 成功；②流式缺失导致 AllPrices 回填命中 V8 字符串上限失败；③下载截断导致 checksum 不匹配。你已确认：triggerKey 改按 UTC 自然日 + 覆盖语义；三个载荷全流式；重启进程自愈 job；能联网重跑真实同步。

## 改动一：triggerKey 改按 UTC 自然日 + 当日报价覆盖（核心架构变更）

**`apps/api/src/modules/pricing/application/price-sync-service.ts:49`**
- 投递 reprice 的 triggerKey 从 `` `price-sync:${runId}` `` 改为 `` `price-sync:${completedAt.slice(0,10)}` ``（`completedAt` 是同步完成时刻的 UTC ISO，取前 10 位 = `YYYY-MM-DD`）。
- 同步传 `priceSyncRunId: runId` 不变（reprice 仍按 runId 取快照），只改 triggerKey 维度。

**`apps/api/src/modules/market/application/market-service.ts:49` 默认 fallback**
- 默认 triggerKey 从 `` `price-sync:${runId}` `` 改为 `` `price-sync:${now.slice(0,10)}` ``（`now` 是 reprice 调用时刻），与显式投递路径一致。

**`apps/api/src/modules/market/application/market-service.ts:74-84` INSERT 幂等策略**
- `ON CONFLICT(sku_id, trigger_key) DO NOTHING` → `DO UPDATE SET price_snapshot_entry_id=excluded.price_snapshot_entry_id, rule_version=excluded.rule_version, reference_price_eur_cents=excluded.reference_price_eur_cents, market_price_amount=excluded.market_price_amount, npc_buy_price_amount=excluded.npc_buy_price_amount, npc_sell_price_amount=excluded.npc_sell_price_amount, npc_buy_fee_amount=excluded.npc_buy_fee_amount, npc_sell_fee_amount=excluded.npc_sell_fee_amount, parameters_json=excluded.parameters_json, reasons_json=excluded.reasons_json, calculated_at=excluded.calculated_at, valid_until=excluded.valid_until`（覆盖全部业务字段，让同日二次同步纠错 + valid_until 续期）。
- `market-service.ts:84-85` 的 `written += changed.changes` 计数语义：DO UPDATE 下 `changes()` 对插入或更新都返回 1，因此 `written` 语义从「新增数」变为「落库数」（新增+更新）。日志/返回值注释同步更新。

**幂等语义变化（需在代码注释+文档说明）**
- 旧：同 triggerKey 重放，第二次跳过（written=0）。
- 新：同日重放，第二次覆盖（written=1），`market_quotes` 仍 1 行（按 SKU+triggerKey 唯一）。即「同日只保留最新业务结果」，业务结果至多一次（按 SKU 维度收敛）。

## 改动二：三个载荷全部流式（下载→边算SHA256写临时文件→流式gunzip→流式JSON）

**新增依赖**：`stream-json`（成熟、零运行时依赖、Node 原生流）+ `@types/stream-json`（dev）。用 `stream-json` 的 `parser` + `pick`/`streamArray` 提取 `data.*` 数组元素。

**`apps/api/src/platform/external/mtgjson/mtgjson-client.ts` 重写下载层**：
- `download(url, ...)`: 不再 `response.arrayBuffer()`。改用 `response.body`（web ReadableStream）→ 转成 Node stream → `pipeline` 同时：① 喂给 `createHash("sha256")`（边下边算，单遍）② 写入 `os.tmpdir()` 下临时文件 `mtgjson-*.gz`。返回 `{ filePath, checksum }`，不返回 Buffer。
  - 增加重试：失败/截断（pipeline 中断）按固定次数重试（如 2 次），记录原因。
  - 用 `try/finally` 确保临时文件在解析后被 `fs.rm` 清理。
- `verifyChecksum(...)`: 不再二次 `createHash().update(bytes)`，改用下载阶段已算出的 checksum 直接比对。
- `decode/parseJson`: 删除全量 `gunzipSync`/`JSON.parse(buffer.toString())`。
- `allPrintingsMappings`: 改为接受临时文件路径 → `fs.createReadStream` → `zlib.createGunzip()` → 把现有字节扫描器改造成流式（按 chunk 维护扫描游标，逐卡产出 `JSON.parse(chunk片段)`）。复用现有 `objectEnd`/`stringEnd`/`isCardsKey` 逻辑，只把 Buffer 入口换成流式 reader。
- `pricesFrom`（AllPricesToday）/ `historicalPricesFrom`（AllPrices）: 改为流式：临时文件 → `createGunzip` → `stream-json` 的 `Pick` 过滤 `data` → `StreamArray` 逐 UUID 元素回调。`historicalPricesFrom` 仍聚合成 `Map<string, MtgjsonHistoricalPrice[]>`（backfill 需要 byDate 分组，聚合在内存是安全的——价格条目本身远小于整个 JSON 文件，触发上限的是「整个 JSON 转字符串」，流式解析后不再发生）。
- `download()` / `downloadAllPrices()` 入口签名不变（仍返回 `MtgjsonPriceSource`/`MtgjsonAllPricesSource`），application 层（price-sync-service / price-backfill-service）**无需改动**。

**临时文件管理**：用 `os.tmpdir()` + 进程内唯一名，解析完成后 `finally` 删除；异常退出靠 OS 清理 `/tmp`。配置项复用现有 `TMPDIR`（dev 脚本已设 `TMPDIR=/tmp`）。

## 改动四：恢复卡住的 job + 重跑 prices.sync（执行阶段，非代码）

1. **重启 API dev 进程**：`worker.recover()`（`task-runner.ts:33`）+ 每次 claim 的 `recoverExpired`（`sqlite-job-repository.ts:65`）会自动把 `locked_until` 已过期的 running `prices.sync` job 重置为 pending（或 attempts≥max 时 dead）。无需手动改库。
2. **重跑 prices.sync**：进程起来后，task-runner 每 5 分钟的 `ensureDailyPriceSyncScheduled` 会按 UTC 日唯一键投递；或经 `POST /v1/admin/prices/sync`（admin）手动触发。环境可联网，会真实下载 MTGJSON → 校验 → 写快照 → 投递 reprice（triggerKey=`price-sync:{今日}`）→ 覆盖写入 `market_quotes`，`valid_until` 续期为 now+15min。
3. **验证（只读查询）**：重跑后查 `market_quotes.valid_until` 应为 `今日+15min`，`/v1/npc-trades/sell/{skuId}/preview` 返回 200 而非 `VERSION_STALE`。

## 风险与边界
- **回归风险最高的是流式重写**。应对：保留适配器对外接口不变；新增 mtgjson-client 独立测试，对 pricesFrom/historicalPricesFrom/allPrintingsMappings 做「流式输出 == 全量输出」的等价性回归（用同一 fixture 分别跑旧全量逻辑的期望值对比）。若等价性测试通过，application 层行为不变。
- **stream-json 新依赖**：首次引入非 workspace 内部依赖。需 `pnpm add stream-json -F @mtg-market/api` + `pnpm add -D @types/stream-json -F @mtg-market/api`，并确认 `pnpm install` 后 `pnpm check` 通过。
- **backfill 不触发 reprice** 的不变量不变（`price-backfill-service.ts` 不动 triggerKey 逻辑，backfill 不调 `enqueueMarketRepriceJob`）。仅 `historicalPricesFrom` 改流式实现。
- **同日覆盖语义**：若当日首次同步数据有误，二次同步纠错——这是你要的行为。但要注意：跨日不覆盖（不同 triggerKey），历史日报价保留不变，符合「每日一个报价版本」。
- **不改**：`market_quotes` schema、`price_sync_state`/`price_sync_schedule_state` 语义、backfill 的 `source_version` 写法、orders/inventory 模块（它们只读 `market_quotes`，覆盖语义对其透明）。
