# I18B：P2P 双边委托预览与订单创建后端 — 实施计划

## 范围与边界

**本期交付（I18B，对应 AT-05A 后端部分）：**
- 双边委托订单数据模型（buy/sell、状态、版本、有效期、审计）。
- 服务端买单/卖单预览：有效限价范围、可用资金/库存、服务端费用、预计支出/到手、卖单保证金规则、预览版本。
- 创建委托：要求未过期预览版本 + 幂等键；买单原子预占资金，卖单锁定库存并预占保证金；拒绝客户端自报费用/保证金。
- 我的买单/卖单、撤单、双边订单簿查询；撤单幂等释放未成交预占。
- `order-rules` 纯函数：限价范围、保证金/费用计算、取消校验。

**明确延后到 I19B/I20B（不在本期）：** 撮合、价格-时间优先、成交价、部分成交、模拟履约、`p2p.trade.settled` 事实事件、`order.expire` 定时任务。

## 已确认的设计决策

1. **买单预占**：`reserveFunds = qty*limitPrice + order_fee`。
2. **卖单预占**：`lockInventory(qty)` + `reserveFunds = fulfillment_deposit`；`order_fee` 不预占，留到 I19B/I20B 撮合/履约时从卖方收入扣除（与 NPC 卖出语义一致）。预览仍同时展示两笔费用。
3. **限价锚点**：以当前 `market_quotes.marketPrice` 为中心 ± 可配置 `limit_price_band_bps`（默认 5000bp=±50%），下限不低于 `market_parameters.minimum_price`。锚点随报价版本变化 → 版本/限价不一致即 `VERSION_STALE`。

## 关键不变量与一致性保证

- **一个短事务**（`InventoryService.withLedgerTransaction` = `withinTransaction`）内同时完成：幂等占位、报价/预览版本校验、`bilateral_orders` 写入、资金预占或库存锁定 + 保证金预占、审计、幂等响应。任一失败回滚，不留半完成状态（与 NPC 交易一致）。
- **资金预占走 `fund_holds`，库存锁定走 `inventory_holds`**：复用 `SqliteUserRepository.reserveFunds/releaseFunds` 与 `SqliteInventoryRepository.lock/release`，`entityType='bilateral_order'`。撤单条件 UPDATE + 状态版本防重复释放。
- **预览版本**：服务端计算，客户端不可编造费用/保证金/限价带；创建必须回传未过期 `previewVersion` + `quoteVersion`。
- **额度**：单笔 `max_quantity_per_order`、用户-SKU-UTC 日 `max_quantity_per_user_sku_day`，按已结算 `bilateral_orders` 聚合（仿 NPC 日额度）。
- **撤单幂等**：状态机 `open/partially_filled → cancelled`，条件 UPDATE 推进 `version`；重放返回首次结果。
- **订单簿只读**：只返回 `limitPrice/remainingQuantity/side`，不含用户身份或敏感字段。
