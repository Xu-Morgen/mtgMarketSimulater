# I26B 实施计划：成就、收藏里程碑与奖励防刷后端

## 设计决策（已与用户确认）
- **处理器位置**：新增 `achievement.process` 独立任务类型（与赛事结算解耦）。赛事结算成功后投递该任务，由 TaskWorker 独立领取；以 `aggregate_id`（报名 ID）为唯一键幂等，失败可独立重试。
- **成就范围**：赛事类（首次参赛/冠军/连胜）+ 卡组类（颜色/系列指挥官）+ 收藏类（收藏里程碑）+ 奖励风控（每日次数/重复参赛）。
- **fact 消费**：直接读 `fact_events` 表（与 `market-service.aggregateFactPressure` 同模式），**不**依赖 outbox（经确认当前无 outbox dispatcher）。

## 架构与权威边界
- 所有可结算逻辑（成就是否解锁、进度计算）在 `packages/rules/src/achievement-rules.ts` 纯函数中，版本化、可重放、不依赖 DB/HTTP/时间。
- API + SQLite 是成就解锁、进度、奖励和审计的唯一写入者；浏览器只展示。
- 成就奖励（GAME_CREDIT/SKU/不可交易徽章）与成就解锁/审计在**同一 SQLite 短事务**内原子完成；不产生半完成状态。
- 历史事件补跑只追加新解锁，绝不重复发奖或覆盖已解锁记录。

## 实施步骤

### 1. 规则包 `packages/rules`
**新增 `packages/rules/src/achievement-rules.ts` + `.test.ts`**
- 导出 `ACHIEVEMENT_RULE_VERSION = "achievement/v1"`。
- 纯函数 + 类型：
  - `AchievementDefinition`：`{ id, kind: "tournament"|"deck"|"collection", category, ruleVersion, goal, reward: AchievementRewardSpec, display: { title, description, badge }, hidden? }`
  - `AchievementRewardSpec`：`{ kind: "GAME_CREDIT"|"sku"|"badge", amount, skuId, badgeId }`（badge 为不可交易展示物）
  - `resolveFirstAchievements(version): AchievementDefinition[]`：返回受控首批成就（迁移固定 ID 对应）
  - `evaluateTournamentAchievements(input: { ruleVersion, definitionIds: string[], profile: TournamentAchievementProfile }): AchievementEvaluationResult`：纯逻辑判断赛事类成就（首次参赛/冠军/连胜）。`TournamentAchievementProfile` = `{ participated, totalWins, consecutiveWins }`。
  - `evaluateDeckAchievements(input: { ruleVersion, definitionIds, commanderColors: ManaColor[], dominantSetCode: string | null }): AchievementEvaluationResult`：判断卡组类成就。
  - `evaluateCollectionAchievements(input: { ruleVersion, definitionIds, distinctSkuCount: number }): AchievementEvaluationResult`：判断收藏里程碑。
  - `evaluateRewardRisk(input: { ruleVersion, rewardsToday, maxRewardsPerDay, repeatParticipationToday, maxRepeatPerDay }): { allowed: boolean; reasons: string[] }`：奖励风控。
- 所有函数显式校验版本与非法输入，返回明确结果（不发奖、不静默回退）。
- **测试**：正常/边界（0、刚好阈值）/非法参数（负数、未知版本、空定义）/重复事件确定性/同输入重放一致。

**修改 `packages/rules/src/index.ts`**：`export * from "./achievement-rules.js"`。

### 2. 数据库 `packages/database`
**新增 `packages/database/migrations/0028_achievements.sql`**
- `achievement_definitions`：受控成就定义（id PK, kind, category, goal_json, reward_json, display_json, rule_version, created_at）。迁移内 INSERT 受控首批成就，与规则包 `resolveFirstAchievements` 的 id 一一对应（id 由迁移固定，与赛事模板同模式）。
- `achievement_progress`：`(user_id, definition_id)` 唯一，`current_value, target_value, status(pending|unlocked), unlocked_at, last_evaluated_fact_id`。
- `achievement_unlocks`：不可变解锁记录 `(user_id, definition_id)` UNIQUE，`source_type(tournament.settled|collection), source_fact_id, source_aggregate_id, reward_kind, reward_amount, ledger_correlation_id, unlocked_at`。唯一约束保证幂等。
- `achievement_reward_grants`：奖励发放流水（GAME_CREDIT/SKU/badge），`(user_id, definition_id)` UNIQUE 防重复发奖；关联解锁与账本/库存 correlation。
- `achievement_risk_counters`：每日风控计数（`user_id, natural_date, rewards_granted, repeat_participations`），唯一键防并发重复。
- 索引：`achievement_progress(user_id)`、`achievement_unlocks(source_fact_id)`（反查来源）。

**修改 `packages/database/src/schema.ts`**：新增 `achievementDefinitions`/`achievementProgress`/`achievementUnlocks`/`achievementRewardGrants`/`achievementRiskCounters` Drizzle 表。
**修改 `packages/database/src/index.test.ts`**：迁移计数 27 → 28；新增成就表存在性断言。

### 4. API `apps/api`
**新增 `apps/api/src/modules/achievements/`**（domain/api/application/infrastructure + README，沿用现有模块分层）：
- **application/achievement-service.ts + .test.ts**：
  - `processFactEvent(input: { factEventId, now })`：在 `withLedgerTransaction` 内读 `fact_events` 该行（必须 `tournament.settled`），解析扁平 payload（`{tournamentId, playerId, result, reward, ruleVersion, randomSeedHash}`，**注意不是 `{payload:{}}` 嵌套**）。按 `aggregateType` JOIN 对应结果表派生 `participated/wins/连胜/颜色/系列`；JOIN 报名快照 `cards_json` 派生指挥官颜色；JOIN `inventory_holdings` 计算 distinct SKU 数（收藏）。调用规则包 `evaluate*` 与 `evaluateRewardRisk`，原子写入 `achievement_progress`/`achievement_unlocks`/`achievement_reward_grants`、发 GAME_CREDIT（`users.funds().creditAvailableFunds` reason=`achievement_reward`）/SKU（`inventory.acquireInLedgerTransaction` reason=`achievement_reward`）/badge、写 `audit_logs`（action=`achievement.unlocked`）。
  - 唯一约束收敛：重复 fact 补跑只 `INSERT OR IGNORE`，已解锁不重复发奖。
  - 风控：每日奖励计数 + 重复参赛计数，超限标记不静默发奖。
  - 查询：`list(userId)`/`progress(userId)`/`unlocks(userId)` 只读投影。
  - **测试**：复用 `tournament-service.test.ts:152` 夹具模式（createArchive/list/insertDeck/insertSnapshot/insertRegistration/settleRegistration 产生 fact）→ 处理 → 断言解锁/发奖/幂等/并发/奖励回滚/重复事件不重复/风控超限。
- **api/achievement-routes.ts + .test.ts**：
  - `GET /v1/achievements`（player）：成就定义 + 进度 + 解锁 + 奖励状态。
  - `GET /v1/achievements/:definitionId`（player）：单成就详情含来源（source aggregate/fact）跳转信息。
  - 全部只读，无幂等键；越权/未登录按现有 `requireRole("player")` 返回 401/403。
  - Fastify inject 测试：权限、空成就、解锁状态、来源反查、重复刷新。
- **README.md**：说明本模块只消费已结算 fact，不写赛事/经济真相外的事实。

## 验收对照（I26B checklist）
- ✅ 成就配置/进度/解锁时间/展示物/奖励/规则版本 → migration 固定 + rules 版本 + DTO
- ✅ 幂等消费 `tournament.settled` + `achievement-rules` + 同事务/幂等任务 + 历史补跑不重复 → `achievement.process` 任务 + `achievement_unlocks` 唯一约束
- ✅ 首批成就（首次参赛/连胜/系列-颜色卡组/收藏进度/冠军）→ `resolveFirstAchievements` + 三类 evaluate
- ✅ 每日次数/重复参赛/异常奖励风控 → `evaluateRewardRisk` + `achievement_risk_counters`
- ✅ achievement-rules 单测（正常/边界/非法/重复/确定性）+ 并发解锁/奖励回滚集成测试
- ✅ 不重复解锁/发奖，可从赛事+流水反查来源 → 唯一约束 + source 字段 + 来源反查 API
