# I32B 发布前后端质量门禁 — 实施计划

I32B 是发布质量门禁迭代，不新增业务功能。交付物是**汇总自动化证据、全局对账、安全门禁、运维告警手册和需求追踪矩阵**，把规则/经济一致性/安全/恢复/部署作为发布阻断条件。基线：`pnpm check` 通过；API 213+1 跳过、rules 81、database 4 全绿。

## 1. 新增：全局经济对账集成测试 `apps/api/src/tests/integration/economic-reconciliation.test.ts`

把 I27B `expectEconomicReconciliation`（只覆盖 2 个玩家、终态无 active hold）升级为**全局、可独立运行**的只读对账套件。用 I27B 同款 seed（开包/NPC/P2P 全链路）驱动一个含**活跃资金冻结 + 订单锁定 + 比赛锁定**的混合状态场景，然后断言全部经济不变量。断言内容（全部为只读 SELECT）：

- **账户恒等式**：每个 `accounts` 行 `total_amount = available_amount + frozen_amount`（DB 已有 CHECK，此为应用层复核）且 `total_amount = SUM(credit) - SUM(debit)`（账本净额）。
- **账本平衡与单调性**：按账户、按 `occurred_at` 排序，`balance_after` 严格等于逐条 credit/debit 重放后的余额（验证 `balance_after` 非任意值）；`balance_after >= 0` 全表。
- **库存恒等式**：每个 `inventory_holdings.quantity = SUM(inventory_entries.quantity_delta)`（entry 净额）且 `quantity = available + order_locked + tournament_locked`。
- **冻结额守恒**：每个账户 `frozen_amount = SUM(fund_holds.amount WHERE status='active' AND account_id=?)`。
- **库存锁定守恒**：每个 holding 的 `order_locked + tournament_locked = SUM(inventory_holds.quantity WHERE status='active' AND holding_id=? AND reason 匹配)`。
- **hold 引用闭包**：所有 `bilateral_orders.reserved_funds_hold_id`、`bilateral_trades.{buyer_funds_hold_id,seller_deposit_hold_id,seller_inventory_hold_id}`、`tournament_registration_holds.inventory_hold_id`、`player_tournament_registration_holds.inventory_hold_id` 指向的 hold 行存在且状态自洽（成交终态时 hold 为 released/captured）。
- **奖励可追溯性**：每个 `tournament_rewards`/`player_tournament_rewards`（reason 为 pool_game_credit）有对应的 `ledger_entries(reason=tournament_reward)`；`achievement_reward_grants(grant_status='granted', reward_kind='GAME_CREDIT')` 有对应 `ledger_entries(reason=achievement_reward)`。
- **事实事件完整性**：`outbox.status` 与 `fact_events` 一一对应；`p2p.trade.settled` 仅出现在 `bilateral_trades.status='fulfilled'`（取消/到期不得有）。

设计为「断言函数 + 两个测试用例」：用例 A 跑完闭环到终态（无 active hold）后全表对账；用例 B 故意停在含 active hold 的中间态验证守恒等式仍成立（验证不是「终态巧合平衡」）。

## 2. 新增：服务端安全门禁集成测试 `apps/api/src/tests/integration/security-gate.test.ts`

把分散在 auth/admin/backup 测试中的安全不变量收敛为**发布门禁级**断言套件（复用现有 seed 与 app 构造，不重复实现业务逻辑）：

- **密码**：注册后 `users.password_hash` 匹配 `$argon2id$`；错误密码 401。
- **会话与角色**：access token 过期/无效 401；普通玩家访问 admin 路由 403；admin 命令（备份触发、活动发布、用户补偿）写 `audit_logs`。
- **CSRF**：refresh cookie 场景缺 CSRF token 被拒。
- **限流**：认证端点第 101 次/分钟 429。
- **输入校验**：非法 payload 返回 `VALIDATION_FAILED` + 统一包络；未知路由 404 包络。
- **CORS**：未列名 Origin 不返回 CORS 头。
- **密钥隔离**：`loadApiConfig` 生产环境拒绝示例 `AUTH_JWT_SECRET` 与默认 `DECK_RESPONSE_ENCRYPTION_KEY`；`NEXT_PUBLIC_*` 检查（grep 确认无服务端密钥泄露到 web 公开配置）。
- **日志脱敏**：onResponse 审计 `summary_json` 不含 password/cookie/token 原文。
