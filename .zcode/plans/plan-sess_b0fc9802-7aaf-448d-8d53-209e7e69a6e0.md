# I30B 管理后台服务端与运营命令 — 实施计划

## 范围与原则

按用户确认，本次完整实现 I30B 全部 checklist 子项并勾选完成、写 `progress/I30B.md`、同步权威文档。遵循 AGENTS.md 权威边界：AdminModule 不跨模块改表，经济补偿通过各模块 application 命令追加流水；所有管理写操作要求 admin 角色 + Idempotency-Key + 原因 + 实体版本 + 不可变审计。

## 架构总览

新建 `apps/api/src/modules/admin/` 四层实现（api/application/domain/infrastructure），复用现有 `requireRole("admin")`、`success/failure`、`isValidIdempotencyKey`、`canonicalizeRequest` 幂等模式、`writeAudit`、`enqueueMarketRepriceJob` 等既有能力。AdminModule 通过 users/inventory/packs/market/catalog/jobs 各模块 application/infrastructure 端口协作，绝不直写他模块表。

## 1. 数据库迁移（`packages/database/migrations/0029_admin_campaigns.sql`）

新增表（均 TEXT UUID 主键、UTC ISO 8601、整数最小货币单位、CHECK 约束）：

- **`admin_campaigns`**：活动草稿与状态机。列：`id, code UNIQUE, name, description, campaign_type CHECK('market_factor'|'price_override_disabled')（首发仅 market_factor）, scope_type CHECK('global'|'set'|'sku'), scope_id, factor_bps CHECK BETWEEN 5000 AND 20000, display_text, starts_at, ends_at CHECK(>starts_at), status CHECK('draft'|'previewing'|'published'|'paused'|'ended'), version INTEGER NOT NULL DEFAULT 1, published_market_event_id, reason, created_by, created_at, updated_at, published_at, paused_at, ended_at`。UNIQUE(code)。索引 status。
- **`admin_campaign_versions`**：不可变草稿/发布版本快照（满足"已发布不可原地覆盖"）。列：`id, campaign_id, version, definition_json, status_snapshot, created_by, created_at`。UNIQUE(campaign_id, version)。
- **`mtgjson_import_drafts`**：MTGJSON 系列/产品/booster 草稿。列：`id, draft_kind CHECK('setlist'|'set'|'sealed_product'|'booster'), source_version, source_checksum_sha256, set_code, payload_json, mapping_status CHECK('pending'|'mapped'|'missing'|'conflict'), mapping_summary_json, status CHECK('draft'|'validated'|'published'|'discarded'), version INTEGER DEFAULT 1, created_by, created_at, updated_at`。UNIQUE(draft_kind, set_code, source_version)。
- 同步给 `packages/database/src/schema.ts` 补充上述新表的 Drizzle 导出（保持 schema.ts 与迁移一致，与既有惯例一致）。

不修改既有 `market_events`、`booster_pack_rules`、`audit_logs`、`users`、`accounts`、`inventory_*` 表结构；通过新表 + 既有表写入实现功能。

## 2. 用户冻结/解冻/会话撤销（轻量迁移 `0030_user_frozen.sql`）

I30B 需要冻结能力，但 `users` 表无状态列。新增 `users.frozen_at TEXT NULL` + `users.frozen_reason TEXT NULL`（轻量 ALTER，不破坏既有数据），CHECK 语义由应用层保证（frozen_at NULL=active）。会话撤销复用既有 `sessions.revoked_at`（admin 批量 UPDATE 该用户未撤销会话）。

## 6. Admin application（`apps/api/src/modules/admin/application/`）

- `admin-service.ts`：编排用例，每个写命令在一个 SQLite 短事务内完成幂等 + 审计 + 跨模块协作：
  - `dashboard()`：聚合只读摘要
  - `listAuditLogs/listJobs/listExceptionTrades`：只读分页
  - 活动用例：`saveCampaignDraft`、`previewCampaign`、`publishCampaign`（校验 → 发布为不可变 market_events → 投递 `enqueueMarketRepriceJob(triggerKey=activity:<version>)` → 审计）、`scheduleCampaign`（定时发布：投递 `runAfter=starts_at`）、`pauseCampaign`、`endCampaign`、`rollbackCampaign`（停用 + 审计）
  - 用户用例：`searchUsers`、`getUserDetail`、`freezeUser`、`unfreezeUser`、`revokeUserSessions`、`compensateBalance`（调 `users.funds()` 追加 admin_compensation credit/debit 账本，不直接 UPDATE 余额）、`compensateInventory`（调 `inventory.withLedgerTransaction` + `adjust` 追加 admin_compensation 流水）
  - 配置用例：`getMarketParameters`、`updateMarketParameters`（版本预览 + 条件 UPDATE + 审计 + 投递 reprice）
  - 同步配置：`enableDisableSeriesSku`、`triggerCatalogSync`、`triggerPriceSync`、`retryJob`（委派 jobs repo）
  - MTGJSON 草稿用例：`createSetlistDraft`（下载 SetList + checksum + 校验）、`createSetDraft`（下载单系列 + 映射到本地 Scryfall 系列代码/SKU）、`previewImportDraft`（展示可导入/缺失/冲突）、`publishBoosterRuleDraft`（调 `packs` application 发布不可变 `booster_pack_rules`）、`discardDraft`
  - 补充包发布用例：`savePackRuleDraft`、`previewPackRule`（服务端候选池/卡位/权重/工艺校验 + 版本预览）、`publishPackRule`（调 PackRepository 发布新版本，UPDATE active_rule_version，不原地覆盖；停用/新版本保留审计）
- 每个写用例返回幂等 resolution（replayed/conflict/in-progress/completed），路由层映射 HTTP 状态。

## 关键不变量

1. AdminModule 只通过 users/inventory/packs/market/catalog/jobs application/infrastructure 端口协作，绝不跨模块写表。
2. 补偿只追加账本/库存流水，绝不直接 UPDATE 余额/库存字段或删除原流水。
3. 活动/补充包规则发布后不可原地覆盖，新版本发布或停用均保留审计。
4. 所有管理写操作：admin 角色 + Idempotency-Key + 原因（适用时）+ 实体版本 + 不可变审计。
5. 日志查询服务端分页、脱敏，不返回敏感原文；不提供删除/修改接口。
6. 外部下载只在受控后台任务中执行，记录来源版本与 checksum，失败保留最近成功数据。
