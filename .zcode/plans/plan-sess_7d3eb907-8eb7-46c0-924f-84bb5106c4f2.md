# I31F：导出与备份状态页面 实施计划

## 目标与边界

I31F 是纯前端轨道，消费 I31B 已实现的后端能力，不新增任何契约、迁移、规则或后端代码。实现 4 项 checklist：

1. **玩家导出入口**（`/exports`）：玩家生成、查看状态、下载自己的 CSV/JSON 经营报表；显示生成中/成功/过期/失败。
2. **管理员备份/恢复演练状态与下载入口**（`/admin/backups`）：列出备份记录、显示状态、受控下载、触发恢复演练。
3. **Playwright 覆盖**导出权限、失败重试、CSV 安全样例和管理员备份状态（桌面 + 390×844 窄屏）。
4. **人工验收记录** `apps/web/tests/manual/I31F.md`。

权威边界遵守 I31B 已确立的事实：浏览器只下载服务端生成的受控 `attachment` 流（文件名来自服务端记录），绝不拼装文件路径、数据库名或 `EXPORT_DIR`/`BACKUP_DIR` 内部路径；金额/概率/报价真相仍只展示服务端响应。

## 关键设计决策

- **二进制下载**：现有 `apiRequest` 把响应 `response.json()`，无法处理文件流。新增一个独立的 `downloadAttachment(accessToken, path)` 工具（放在 `apps/web/api/client.ts`），用 `fetch` 取 `blob()` 后 `URL.createObjectURL` + 临时 `<a download>` 触发下载，从 `Content-Disposition` 提取服务端文件名。不改动 `apiRequest`，避免影响所有既有 JSON 路由。
- **导出页角色门禁**：后端 `requireRole("player")` 只校验认证不校验角色，所以 admin 也能调用（与 inventory/market 等玩家页一致）。导出页用玩家 shell `allowedRoles={["player","admin"]}`，但列表查询的 query hook `enabled` 条件以 `accessToken && user` 为准（不限定 admin），生成/下载同 player 一致。导航加入玩家侧栏。
- **管理员备份页**：用 `AdminShell`（`allowedRoles={["admin"]}`），加入管理侧栏导航。恢复演练是只读校验（绝不覆盖运行库），用二次确认对话框 + 服务端结果展示（完整性、核心表、采样计数）。
- **CSV 安全样例 e2e**：I31B 集成测试已验证 `csvEscapeCell` 转义 `=cmd|malicious`。前端层面无法在浏览器重算 CSV（那会违反权威边界），所以 Playwright 的 "CSV 安全样例" 用 route mock 让下载接口返回一个含 `'=evil` 已转义内容的 blob，断言浏览器下载的内容里 `=evil` 不作为裸公式出现（即前缀 `'`）。这验证前端下载链路不破坏服务端的转义，且不在浏览器重新拼装 CSV。

## 实施步骤

### 1. 新增 `apps/web/api/export-api.ts`（玩家导出 API）
- 复用 `apiRequest` + `downloadAttachment`。
- `exportApi`：`list(accessToken)` → `GET /v1/exports`；`generate(accessToken, formats, idempotencyKey)` → `POST /v1/exports`；`downloadUrl`/`download` → `GET /v1/exports/{id}/download`（调 `downloadAttachment`）。
- TanStack Query hooks：`useExportsQuery`（enabled `accessToken && user`，带 `refetchInterval` 当存在 `running` 记录时每 2s 轮询，与 catalog-sync 模式一致）。
- Mutation：`useGenerateExportsMutation`（组件层 `createIdempotencyKey()`，成功失效 exports 查询）。
- 下载直接在组件层调 `exportApi.download`（非 mutation，因为是副作用），用 try/catch + toast 处理 404（过期/越权）与失败。

### 2. 新增 `apps/web/features/exports/exports-page.tsx` + `exports-page.module.css`
- 标题 + intro（说明只下载服务端生成的文件，CSV 已做公式注入防护，过期会自动清理）。
- 生成区：格式勾选（CSV/JSON，至少 1 项）→ 二次确认 `ConfirmDialog` → 提交，提交期间禁用、成功 toast + 失效列表。
- 列表表格：文件名、格式、状态（生成中/成功/过期/失败，用 `.draft/.published/.ended/.failed` 已有样式 tag）、大小、过期时间、生成时间、下载按钮（仅 `succeeded` 可点，过期/失败禁用并显示原因）。
- 状态覆盖：`PageSkeleton` / `ErrorState` / `EmptyState`。
- 文案与产品术语一致（中文）。

### 3. 扩展 `apps/web/api/admin-api.ts`（备份/导出管理 API）
- 在 `adminApi` 对象追加：`backups(accessToken, limit)`、`backup(accessToken, id)`、`triggerBackup(accessToken, kind, idempotencyKey)`、`restoreRehearsal(accessToken, id, idempotencyKey)`（POST）、下载经 `downloadAttachment`。
- 新增 query hooks：`useAdminBackupsQuery`、`useAdminBackupQuery(id)`（enabled admin && id）。
- 新增 mutations：`useTriggerBackupAdminMutation`、`useRestoreRehearsalAdminMutation`（各 `createIdempotencyKey()`，成功失效 backups 列表）。
- 在 `adminKeys` 加 `backups: ["admin","backups"]`，`invalidateAllAdmin` 自动覆盖。

### 4. 新增 `apps/web/features/admin/admin-backups-page.tsx`（复用 `admin-shared.module.css`）
- 顶部统计（总备份数、成功数、最新成功时间/SHA-256 前 12 位、保留份数从 env 注入只读展示——但 env 不暴露给浏览器，所以只展示服务端记录里的 latest succeeded 摘要，不展示 `BACKUP_DIR`）。
- 触发备份区：`manual`/`predeploy` 选择 → 二次确认 → 提交。
- 备份列表表格：文件名、kind（scheduled/manual/predeploy）、状态、大小、完整性、SHA-256 前 12 位、创建时间、完成时间、操作（下载、恢复演练）。下载/演练均二次确认。
- 恢复演练结果用对话框展示（`sqliteIntegrityOk`、`coreTablesPresent`、`sampleCounts`），明确"只读校验，绝不覆盖运行库"。
- 错误状态：403 → "无权查看备份"。

### 5. 新增 App Router 页面
- `apps/web/app/(player)/exports/page.tsx` → `<ExportsPage />`（在 player shell 内，`allowedRoles={["player","admin"]}`）。
- `apps/web/app/admin/backups/page.tsx` → `<AdminBackupsPage />`（admin shell）。

### 6. 扩展导航 `apps/web/components/navigation-shell.tsx`
- 玩家侧栏 links 追加 `{ href: "/exports", label: "我的数据导出" }`。
- 管理侧栏 links 追加 `{ href: "/admin/backups", label: "备份" }`。

### 7. Playwright `apps/web/tests/e2e/exports-i31f.spec.ts`（桌面 + 窄屏各跑一遍）
采用 `admin-i30f.spec.ts` 的 route-mock 模式（mock session cookie + API responses，不依赖真实后端），覆盖：
1. **玩家生成导出并下载；重复点击只投递一次**：mock `POST /v1/exports` 计数，断言生成按钮提交期间禁用、成功后列表出现 succeeded 记录、下载触发 blob（route fulfill 一个含 `'=evil` 的 text/csv，断言下载文本含 `'` 前缀且不含裸 `=evil`）。
2. **过期/失败状态与失败重试**：mock 列表含一条 `expired` 与一条 `failed`，断言下载按钮禁用、失败原因展示；重试生成（新幂等键）成功后列表刷新。
3. **CSV 安全样例**：验证下载链路不破坏服务端转义（前述 blob 断言），且页面不在浏览器拼装 CSV（断言无 `<textarea>`/编辑器或本地 CSV 文本）。
4. **管理员备份状态与下载**：mock admin session，`/admin/backups` 列表展示状态/完整性/SHA-256 摘要；下载触发受控流；恢复演练二次确认后展示只读校验结果；普通玩家深层链接 `/admin/backups` 显示 403（与 I30F 一致，由 SessionGate 重定向 `/forbidden`）。
